# Mini PDB

KiCad 10 project for a minimal power distribution board: solder pads for a battery, a load, and an off-board switch in series with battery +. 20 × 10 mm, two M2 mounting holes, 2 layers, no components.

- KiCad project: `MiniPDB.kicad_pro` at the repo root (folder name matches the project name, which the kicad MCP server relies on). The `.kicad_pro` was copied from SolarNodeChargeController so the design rules match (0.2 mm clearance, 0.5 mm copper-to-edge, 0.8 mm min silk text).
- Schematic: `MiniPDB.kicad_sch`, single A4 sheet, generated by `tools/gen-schematic.js`.
- PCB: `MiniPDB.kicad_pcb`, generated by `tools/build-pcb.py` (placement, copper, zones, silk, outline in one script).
- Footprint library: `MiniPDB.pretty` (project `fp-lib-table`), one footprint `WirePad_1x02_SMD_2.9x3.6mm_P5.0mm`.
- Images: `docs/images/` — `schematic.svg`, `pcb-top.png`, `pcb-bottom.png`, `pcb-iso.png`. `output/` (gitignored) holds ERC/DRC reports and the netlist.

## Status

Schematic and board complete. ERC 0 items (all severities); DRC 0 violations, 0 unconnected, 0 schematic-parity issues. Gerber package generated (see **Fabrication**). Not yet: a panel file, physical review of pad size against the wire gauge actually used.

## Circuit

```
J1 BATTERY  1 BAT+ ──── J2 SWITCH 1      J2 SWITCH 2 ──── J3 LOAD 1 VOUT
            2 GND  ─────────────────────────────────────── J3 LOAD 2 GND
```

| Ref | Value | Footprint | Pins |
|---|---|---|---|
| J1 | BATTERY | MiniPDB:WirePad_1x02… | 1 = BAT+ (top pad), 2 = GND |
| J2 | SWITCH | MiniPDB:WirePad_1x02… | 1 = BAT+ (top), 2 = VOUT. Off-board SPST, non-polar |
| J3 | LOAD | MiniPDB:WirePad_1x02… | 1 = VOUT (top), 2 = GND |
| H1, H2 | M2 | MountingHole:MountingHole_2.2mm_M2 | non-plated |

Nets: `/BAT+`, `/VOUT`, `GND`. J1–J3 are `Connector_Generic:Conn_01x02` symbols with `in_bom no` (bare pads; the footprint is `exclude_from_bom`/`exclude_from_pos_files`, and the two must agree or DRC parity complains).

Interpretation of the request: "pads for soldering a battery, a load, and a switch" was read as wire pads for an external switch, not an on-board switch. Small on-board slide switches are typically rated ≤0.5 A, which defeats a PDB.

## Board

20 × 10 mm, sharp corners (`CORNER = 0`; was 1 mm radius until the user chose V-score panelization — rounded corners would force tab/mouse-bite routing with ~2 mm gaps), board top-left at (100, 100) in the editor. Copper is ≥0.5 mm from every edge (pads 0.7 mm from the long edges), which meets the usual ≥0.4 mm copper-to-V-score rule. Left to right:
- **H1** M2 hole at x = 2.3 mm (hole courtyard r = 2.45 ends at 4.75; M2 head r = 1.9).
- **Pads:** three columns at x = 6.5 (J1 BAT), 10.0 (J2 SW), 13.5 (J3 OUT); pads 2.9 × 3.6 mm, rows at y = 2.5 (+) and 7.5 (−), 0.6 mm column gap, 1.4 mm row gap. Fits wires up to ~16 AWG.
- **H2** M2 hole at x = 17.7 mm.

Copper:
- **F.Cu:** only the pads plus a 3.0 mm bridge from J1.1 to J2.1 (BAT+). Round ends stay inside the pads.
- **B.Cu:** two zones, both clear of the hole areas (x 4.8–15.2). VOUT (priority 1): L-shape under the J2 top pad, the top 1.2 mm of J2.2 and all of J3.1. GND (priority 0): fills the rest — under J1, a 2.3 mm strip along the bottom edge under J2.2, and under J3.2. This is how J2.2→J3.1 (VOUT) and J1.2→J3.2 (GND) cross.
- **Vias:** 0.8/0.4 mm via-in-pad, tented on the back (board default): 3 in J2.2 (top edge), 6 in J3.1, 6 in J1.2, 6 in J3.2. Grouped toward the outer pad edges so y 3.0–5.9 on the back is free for silk.
- **Current:** bottlenecks are the 3 VOUT vias in J2.2 and the 2.3 mm × ~3.5 mm GND neck on B.Cu; both put the board at roughly 5 A continuous on 1 oz copper (very short necks, so real heating is lower than the IPC-2221 trace figure). For more, order 2 oz copper; the layout doesn't need to change.

Silkscreen: front — `BAT` / `SW` / `OUT` (0.8 mm) in the gap between the pad rows, `+` / `-` (1.2 mm) beside each row at both ends next to the holes. Back — "Mini PDB v1.0" / "by JaisorGadgets", centred between the via groups.

## Regenerating the design

From the repo root:

```bash
node tools/gen-schematic.js
kicad-cli sch erc --format json --severity-all -o output/erc.json MiniPDB.kicad_sch
kicad-cli sch export netlist --format kicadxml -o output/net.xml MiniPDB.kicad_sch
"C:/Program Files/KiCad/10.0/bin/python.exe" tools/build-pcb.py output/net.xml
kicad-cli pcb drc --schematic-parity --severity-all --format json -o output/drc.json MiniPDB.kicad_pcb
```

Images:

```bash
kicad-cli sch export svg --exclude-drawing-sheet -o docs/images MiniPDB.kicad_sch   # then rename MiniPDB.svg -> schematic.svg
kicad-cli pcb render --side top --quality high -w 1600 -h 900 -o docs/images/pcb-top.png MiniPDB.kicad_pcb
kicad-cli pcb render --side bottom --quality high -w 1600 -h 900 -o docs/images/pcb-bottom.png MiniPDB.kicad_pcb
kicad-cli pcb render --side top --quality high --rotate "-40,0,25" --perspective -w 1600 -h 1000 -o docs/images/pcb-iso.png MiniPDB.kicad_pcb
```

- Each script overwrites its output. **Once anyone edits the schematic or board in KiCad, stop regenerating that file**: port the edits into the scripts first, or switch to editing in KiCad.
- Before writing, check the editor for that file is closed (`~*.kicad_sch.lck` / `~*.kicad_pcb.lck`); afterwards the user must close the editor without saving and reopen.
- UUIDs in the schematic are deterministic (SHA-1 of the item key), so regenerating keeps the PCB footprint links stable.

## Fabrication

`output/fab/MiniPDB_v1.0_gerbers.zip` (gitignored; attach to a release tag): 7 Gerber X2 layers (F/B copper, mask, silkscreen, Edge.Cuts), Gerber job file, separate PTH/NPTH Excellon drill files and drill maps. No paste layers: nothing is assembled and the pads have no paste. Checked: job file says 2 layers / 1.6 mm / 20 × 10 mm (20.05 × 10.05 including the outline stroke); PTH = 21 × 0.4 mm (vias), NPTH = 2 × 2.2 mm; B.Mask opens only the two M2 holes, so all vias are tented on the back.

Order settings: 2 layers, FR-4 1.6 mm, 1 oz copper (2 oz for >5 A), min track/space 0.2/0.2 mm, min drill 0.4 mm, any mask colour. For a matrix, either let the fab panelize with V-score or supply a panel (not made yet).

Regenerate (after DRC is clean):

```bash
OUT=output/fab
kicad-cli pcb export gerbers --layers F.Cu,B.Cu,F.Silkscreen,B.Silkscreen,F.Mask,B.Mask,Edge.Cuts --subtract-soldermask --check-zones -o $OUT/gerbers MiniPDB.kicad_pcb
kicad-cli pcb export drill --format excellon --excellon-units mm --excellon-zeros-format decimal --drill-origin absolute --excellon-separate-th --generate-map --map-format gerberx2 -o $OUT/gerbers/ MiniPDB.kicad_pcb
python -c "import zipfile,os; z=zipfile.ZipFile('$OUT/MiniPDB_v1.0_gerbers.zip','w',zipfile.ZIP_DEFLATED); [z.write(os.path.join('$OUT/gerbers',n),n) for n in sorted(os.listdir('$OUT/gerbers'))]"
```
